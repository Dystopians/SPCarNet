# v96-v99 Checkpoint-Baked Interface Fix and Negative Evidence

Date: 2026-06-25

## Executive Summary

This round tested whether the Phase-J / ELA render-time repair signal can be baked back into a topology-frozen MeshSplatting checkpoint. It did **not** pass the counter promotion gate.

The main concrete progress is an interface fix: parent-aware teacher masks now receive parent renders even when parent rollback loss is disabled. The fix made v98b/v99 valid mechanism tests, but both still fail the pre-declared counter anchor. The current conclusion is therefore not “checkpoint-baked recovery is solved”; it is that the Phase-J gain appears to rely on guarded, view-conditioned residual transfer that is not absorbed by the static checkpoint parameterization with the tested losses.

## Real Code Change

File changed:

```text
scripts/car_model/meshsplatopt_run_strict_compact_recovery.py
```

Problem found during v98:

```text
[TeacherRender] parent-aware mask disabled for this run: no parent renders were loaded.
```

Root cause: the strict recovery launcher only forwarded `--parent_render_rollback_dir` to `train.py` when `parent_render_rollback_lambda > 0`. Parent-aware teacher modes such as `teacher_better_current_parent_changed` need parent renders even when rollback loss is intentionally disabled.

Fix: if `teacher_render_mask_mode` contains `parent`, the launcher now forwards `--parent_render_rollback_dir` independently of rollback-loss activation. It does **not** enable rollback loss unless `parent_render_rollback_lambda > 0`.

Validation:

```text
python3 -m py_compile scripts/car_model/meshsplatopt_run_strict_compact_recovery.py scripts/car_model/run_v96_checkpoint_baked_certified_repair_scene.py train.py
```

Dry-run contract confirmed `parent_render_rollback_dir` is retained with `parent_render_rollback_lambda: 0.0`.

v98b/v99 runtime logs confirmed:

```text
[ParentRenderRollback] loaded 210/210 train renders ...
```

## Interpretation

The parent-aware interface fix was necessary, but it did not unlock the desired gain. Once the parent-aware mask actually loaded parent renders, the best result improved only marginally over the invalid v98 run and still missed the gate.

This supports the current bottleneck hypothesis:

```text
Phase-J works because it performs guarded, view-conditioned residual transfer at render time.
The standard MeshSplatting checkpoint parameters cannot faithfully absorb that signal
through short topology-frozen RGB distillation without losing held-out quality.
```

For the paper story, this is useful negative evidence but not a promoted endpoint. The paper-safe endpoint remains the Phase-J guarded adaptive ELA result, not v96-v99 checkpoint-baked recovery.

## Next Action

Do not expand v96-v99 checkpoint-baked recovery to hard-triad/full9 unless a new counter run clears all three gate metrics.

The next mechanism should be representation-level rather than another loss-weight tweak:

```text
Implement a compact, checkpoint-attached residual field that is evaluated at render time
with the same policy-val / parent-improvement gate as Phase-J, instead of trying to
distill the residual into static triangle colors and weights.
```

The immediate command-level continuation should launch a new implementation branch for a lightweight residual-field endpoint, not another v96-style recovery run.
